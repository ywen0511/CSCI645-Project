# Post-release V3 maintenance

The scientific V3 study remains completed at `v3.0.0`; these repairs do not change its
physics, policy checkpoints, frozen suites or published numerical results.

## Findings and changes

- The root README still described preparation-only status after the study had been
  released. README, AGENTS and historical assignment entry points now distinguish
  completed V3 evidence from the active `POST_V3_EXECUTION.md` continuation.
- Reproduction mixed paths after changing directories, passed an unresolved
  `$DELIVERY` matrix directly to the evaluator, and described a 65-case job as one case.
  The revised instructions use separate absolute tooling/delivery/experiment paths,
  the placeholder-aware runner, fresh output roots and full 65-case completion.
- The task ledger previously checked only output existence. The runner now fingerprints
  file contents and directory membership, hashes matrix dependencies/checkpoints,
  records resolved execution context and considers only the latest attempt. Changed
  completed outputs or unverifiable legacy provenance fail closed; missing outputs
  can resume via the underlying evaluator. `--dry-run` resolves inputs without launch.
- The original freeze hashed the pre-final `SUITES.json`; final generation then added
  its final entry, preventing the creation command from being rerun. The new archived
  suite rebuilder checks original Git bytes, permits only that historical metadata
  addition, and verifies generated bytes against all three archived suites. It never
  rewrites the freeze or original creation script. This repairs reproducibility, not
  the timing or scientific meaning of the historical preregistration.

## Validation boundary

CPU regressions cover output corruption, directory changes, changed dependencies,
legacy provenance, failed latest attempts, dry-run, cached reuse and non-mutating
rebuild of the actual immutable experiment. The check and copy modes both reproduce
312 development, 240 validation and 2,600 final cases; copies refuse overwrite.
See `results/post_v3/maintenance_cpu.json` for executed commands and results.

No GPU, Isaac Lab or Isaac Sim workload is run by the local preparation agent.
Fresh download, table regeneration and simulator replay/resume of the revised workflow
remain Stage A of the remote assignment. Historical published verification is not a
new test of these changes. V4 is an authorized, separately frozen research extension;
its implementation/results are not claimed here.
